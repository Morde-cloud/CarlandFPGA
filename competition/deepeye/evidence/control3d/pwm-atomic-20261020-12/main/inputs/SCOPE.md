## Exact internal interface and semantics (normative candidate)

Module deepeye_atomic_pwm. Parameters COUNT_W=32 (supported 2..32), TAG_W=32 (supported 1..64). All inputs synchronous to rising clk; synchronous active-high rst and stop. Inputs cfg_valid, cfg_period[COUNT_W-1:0], cfg_high_yaw/pitch/speed[COUNT_W-1:0], cfg_tag[TAG_W-1:0]. Outputs cfg_ready, accepted, rejected, applied, frame_start, running, pending, pwm[2:0] (bit0 yaw, bit1 pitch, bit2 speed), active_period, active_high_yaw/pitch/speed, active_tag. Output pulses describe the edge just sampled and last one cycle; adjacent events may stay high for adjacent cycles.

One complete pending tuple and one active tuple, never partial per-channel state. cfg_ready is high iff !rst && !stop && !pending; it does not depend on cfg_valid or payload. Transfer occurs when cfg_valid && cfg_ready at the edge. Valid tuple: period >=1 and each high <=period (unsigned). A legal transfer snapshots the entire payload and pulses accepted. An invalid transfer pulses rejected, not accepted, and changes neither active nor pending state. Valid held when not ready has no effect; no rejected pulse. Upstream must hold or withdraw its request as ready/valid requires.

Old-state scheduling: at an ordinary edge, a pre-existing pending tuple applies iff idle or the current phase is the old active period minus one. Application atomically updates every active field, empties pending, sets phase=0/running=1, pulses applied and frame_start, and sets all output levels from new high>0. An incoming transfer on that same edge never bypasses the pending stage. Because pending pre-state makes cfg_ready false, an applying edge cannot accept a replacement. This intentional one-edge backpressure bubble removes overwrite ambiguity.

If idle with no pre-existing pending, a new legal transfer only queues; output stays low until the next edge applies. If running, a new legal transfer at a frame-boundary edge with no old pending queues while the old active tuple starts another complete frame; it applies at the following boundary. A tuple accepted mid-frame applies at the next boundary. If no pending update, frames repeat indefinitely; TTL/authority gating remains external and is not claimed.

Frame timing is measured in whole clk intervals following sampled edges. On a start edge phase=0. Each ordinary subsequent edge increments phase until phase=period-1; next edge wraps/applies to phase=0 and asserts frame_start. Each channel is high for exactly its first high-count intervals and low for the rest. high=0 is always low; high=period is continuous high across repeated frames. period=1 is valid and starts a frame every edge. Counter must never overflow or evaluate period-1 while idle/period=0. Outputs pwm must be registered, with no combinational gating by stop/rst/input payload; no asynchronous/stopped-clock emergency guarantee.

Priority rst or stop overrides every handshake, invalid request, pending apply and frame boundary on that edge: running/pending/pwm/all active metadata/phase/pending metadata become zero and all pulses are zero. While either asserted cfg_ready=0. Deassertion alone never resumes old output; a fresh accepted tuple is required. Held stop/rst remain quiescent. Synchronous flush may truncate a high pulse; this is specified abort behavior. There is no per-request cancel input beyond global stop. Unknown/X behavior and analog/metastability/CDC/RDC are outside the digital accepted domain; unsupported parameter elaborations must fail simulation early, not silently clip.
