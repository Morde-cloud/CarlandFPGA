Five independent architecture candidates:
P1 codec-first full-curve lossless uplink and remote NPU guidance: best exact reconstruction and simplest baseline; infeasible for all random/noisy input at 240 bit/s and vulnerable to stale decisions.
P2 bounded-error progressive waveform telemetry and remote NPU: predictable resource budget and useful live curve; quantization/decimation changes semantics and needs independently specified error plus risk preservation contract; reject as first MVP, retain explicit optional mode.
P3 FPGA feature/event extraction, semantic uplink, surface NPU diagnosis: fastest telemetry and strong hardware data reduction; missed features irrevocably destroy evidence and can undermine data observability; retain event path, not sole truth.
P4 local deterministic protection plus event-priority and independent lossless curve blocks, NPU supervisory slow loop, physical HIL: recommended backbone; causality can be proved, hard deadlines local, preserves informative samples, tolerates NPU/link failure. Complexity lies in arbitration/freshness state machine.
P5 NPU-directed active sensing/compression/trajectory selection plus FPGA acquisition execution: highest distinctiveness, can use link budget on uncertainty; needs sensor action effects and explicit exploration bounds, difficult to validate and vulnerable to delayed control; retain slow profile suggestions only after fixed profile baseline passes.

Fused selection P4+: borrow P1 bit-exact independently decodable blocks, P3 immediate timestamped priority events with raw evidence references, P2 explicit declared bounded-error/degraded mode only after integrity and risk regression, P5 offline oracle-derived profile labels and slow hysteretic recommendations. NPU performs risk inference/uncertainty/slow guidance; CPU decodes. PL owns acquisition timestamp, bounded queues/CRC, hardware output, local safety FSM and command freshness. Do not promise 4:1/8:1, NPU speedup, water detection or global optimum from this qualitative review.

Deterministic counterexamples/corrections:
1) 240 bit/s 8N1 =24 B/s. PDF RAW:4*45/3.2=56.25 B/s before control; normal 4:1+ACK+periodic event=44/3.2+14/3.2+18/30=18.725 B/s (78.02%). RAW queue grows >=32.25 B/s without deliberate discard; 96 B queue ideal fluid fill ~2.98 s, 32 KiB ~1016 s excluding control. Two-frame cap bounds latency/memory by losing data, not sustaining all data. Require conservation counters generated/sent/dropped/local-retained and honest remote coverage.
2) Nonpreemptive 48B current frame plus14B ACK plus18B event occupies(48+14+18)/24=3.333 s. Newly ready curve with latest-sample age near0 can cross PDF's2s pre-send expiry even in average-underloaded normal operation. Need explicit classes/token budgets/reserved curve service and end-of-service age policy; verify burst schedule, not just average utilization.
3) Same current sensor history can arise from conductive non-water layer and conductive water layer. Any deterministic model receives identical tensor and must produce same output, so at least one distinct water label fails. Demonstration claims must be simulated risk/low-resistivity anomaly under stated observation model; physical water classification requires independent discriminative measurement/labels.
4) Command duplicate TTL ambiguity: original valid command accepted at t0 TTL10s; retry same seq at t7 with observation age7s passes stated8s freshness. If duplicate handling resets TTL/watchdog, execution extends from t10 to t17. Idempotent rule must preserve original apply time/expiry and duplicate response must not count as fresh decision. This is a missing specification, not a proven existing RTL defect.
5) 24bit100Hz observation counter wraps after46.603h. SESSION notification alone cannot establish correctness when lost or delayed. Require wrap-safe serial comparison, session/boot epoch and loss tests; reject unknown epoch before enable.
6) Baseline average event delay formula excludes arbitrary ACK/event queue and oldest-to-newest32-sample window age. Separate maximum packet blocking, event admission-to-output, first-observable-risk-to-output and full data-window freshness. Report drops/masks; do not substitute received valid samples for full raw curve.
7) NPU provider configured does not prove useful nodes on NPU; CPU fallback can execute all relevant operations. Require operator assignment report and actual runtime profiling, then CPU same-model baseline. Tiny 4x32 input model may have no latency advantage; do not inflate workload solely to manufacture benefit.
