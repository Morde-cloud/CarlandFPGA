# B 机计划书任务中断调查与修复

任务：`B-INTERRUPT-20261014/v1`。调查日期：2026-10-14。本文时间均为北京时间（UTC+8）。

## 结论和证据

截图中的两次中断源于本地调度器：它收到任何新的人类消息后，都会取消正在执行的模型调用，未区分普通补充、进度查询、其他任务和明确暂停。新增消息因此打断了计划书任务。被取消的任务随后命中网关的恢复保护，输出截图中的“失败或中断……不自动重放”提示。该保护用于避免重复执行有副作用的工作，应当保留。

从 B 机持久账本只读提取的时间线：

| 被中断任务 | 新消息入库 | 任务记为 interrupted | 间隔 | 新消息内容类别 |

| `task-6d0ed945aa2915e661bc8ced` | 2026-10-14 00:08:59.663717 | 2026-10-14 00:08:59.716048 | 52.331 ms | 另一成员补充资源问题 |
| `task-fed7c6df68d97d7fbeb7d4ba` | 2026-10-14 00:20:09.127437 | 2026-10-14 00:20:09.180561 | 53.124 ms | 物料配件自主规划说明 |

两条模型运行记录均保存错误 `turn cancelled`。旧代码在 `Controller.offer()` 中直接对任意 `SourceKind.HUMAN` 执行 `_active_dispatch.cancel()`；网关收到取消后中断模型轮次并持久化 `interrupted`。上述时序、代码路径及旧版本可重复失败共同支持本次根因结论；这不是对其他历史网络故障的排除结论。

完整聊天和任务数据库未上传；原始只读提取保存在 B 本地 `interruption-20261014/incident-private.json`。本目录只包含脱敏结论、测试输出和验收记录。

## 修复行为

- 普通人类补充、进度查询、无关任务及尚未归属的新共享任务持久化排队，不取消当前执行；当前轮次结束后重新读取优先级，人类消息先于尚未开始的 peer 工作。
- 有效的明确暂停仍可中断；同一任务更高版本的人类指令仍可替代旧版本。过期/陈旧暂停及恢复指令不误取消当前工作。
- 被新的人类任务版本替代的旧 peer 工作不再被重新派发。
- 允许的中断记录 `dispatch_preempted` 审计事件，保存原因及触发/被触发消息标识，避免下次只有模糊的取消错误。
- 保留失败/中断任务的恢复保护；没有修改历史状态，没有盲目重放旧计划书任务。

明确暂停可使用已有 `/fpga pause` 指令。普通群消息现在会等当前模型轮次结束后处理，不承诺在当前推理轮次中即时生效。[Codex 官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 区分追加输入 `turn/steer` 与取消轮次 `turn/interrupt`；本修复采用现有持久队列，不引入新的模型调用接口。

## 验证

1. 在隔离的当前 B 运行代码副本上，只加入新的回归测试，旧调度器稳定失败：普通资源补充错误取消正在研究的任务。见 `before-reproduction-stderr.txt`。
2. 覆盖候选调度器后，调度、连续性、网关、会话、运行时、飞书通道和持久存储七组测试共 **95 项通过**。见 `candidate-regression-stderr.txt` 和 `validation.json`。
3. 测试使用隔离数据库和受控网关，不调用真实模型，不操作板卡，不注入真实飞书/peer 队列。测试输出中的现有事件循环 ResourceWarning 不影响通过结果。
4. 另在上游基线 worktree 上完成 25 项调度测试和 68 项相关集成测试；主要验收证据采用上述更贴近 B 实际运行环境的 95 项结果。

部署必须先通过已有更新器的数据库写入围栏确认空闲，再更新唯一运行文件 `fpga_mesh/controller.py`。保留计划任务原动作、启动器、节点身份、凭据、Git 工作区其他改动和全部持久队列。部署结果以另附的实测记录为准；单元测试通过本身不表示生产服务已经加载修复。

本次工作不含 A/C 服务变更、硬件验证或计划书算法验收。明确的人为暂停、应用退出及机器/网络故障仍可能中断任务；本修复针对已定位的普通群消息误取消问题。
