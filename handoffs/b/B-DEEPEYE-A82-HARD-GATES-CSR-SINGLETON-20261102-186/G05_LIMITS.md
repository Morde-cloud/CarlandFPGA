Multiple original100ms STEP calls per admitted command are conditionally possible within the original runtime. Every call needs current Root/revision, no overlap with prior committed interval, live actor/health, same clock, source age and a final before_commit fence. Its whole interval must fit the minimum command/source/health/actor/session/previous-action bounds. A 1000ms prospective command can contain at most10x100ms with zero overhead, usually fewer; FAST3000ms is not a new1000ms command grant. Displaying movement or safe STOP is not complete red-circle exit.

A software-only bounded navigation proposal may keep the current RTL TTL/ROM/register layout if every real command remains legal and the matched loaded pair is qualified. It must version together session caps/status budget, protocol message/TRACE/status quotas, total-I/O and cumulative reply storage/transport, finite source/invocation/STEP history and run/session duration. Select concrete maxima prospectively, model every hidden access and reserve room for bounded close/failure evidence. A bounded streaming receipt design must retain exact order/identity/continuity, rather than dropping evidence to fit1MiB. Any >10s change also reaches G05Port._bind_deadline, board/client deadline validators, original source and actor run horizons. Do not reset budgets by reopening an old consumed issuer or relabel a new session as the old one.

No BIT change is requested solely by the software caps. No final compatibility, physical feedback, timing or 16-command demo is proved by this source review.
